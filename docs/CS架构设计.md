# 客户端—服务端架构：当前目标与边界

实现更新：本篇保留原始设计记录。当前网页web/和server/FastAPI已实现，认证采用服务端不透明令牌+HttpOnly Cookie，不是客户端自报user_id；实际接口带/api前缀。功能与限制以项目README和《网页版-启动与边界》为准。

用户新要求：本项目采用CS架构。此文是设计约定，尚未实现HTTP服务、客户端联网、登录认证或SSE接口；现有chat仍是本机直连模型的开发入口，不冒充已完成CS。

## 客户端Client

第一版保持Python终端客户端，不强制改成网页。未来client/负责用户输入、登录凭据使用、列出/选择会话、通过HTTP发送任务、解析服务端SSE、显示回复和取消操作。以后可以换桌面或Web客户端，而不重写核心逻辑。清理时已移除只有占位说明的client/server/tools目录，等实现时再创建；下述目录名表示计划，不是当前已存在的功能。

客户端不持有DeepSeek Key，不直连DeepSeek，不直接访问SQLite，不自行决定用户归属或缓存策略。客户端自己的登录令牌与DeepSeek Key是两种不同凭据，都不能写进日志或URL。

## 服务端Server

server/作为FastAPI入口和应用服务层，负责请求校验、认证/当前用户、会话归属检查、流式任务生命周期、错误映射，再调用现有核心模块：
- agents/：LangGraph编排，单任务State。
- models/：LangChain/DeepSeek，仅服务端拿模型Key。
- prompt/：提示词与上下文模板。
- memory/：短期上下文、长期偏好策略、工作记忆生命周期。
- storage/：SQLite用户/会话/轮次/摘要，所有读写带服务端确认的user_id。
- cache/：应用回答缓存及后续工具缓存，用户与会话范围不变。
- tools/mcp/：服务端连接受信MCP服务；不把客户端工具清单当授权。
- log/：结构化运行记录，后补request_id/turn_id与任务关联。

SQLite和运行数据只在服务端目录/机器上，CLI客户端不能读。启动本地CS时两端先都在Mac、分两个进程；不是一定需要购买云服务器。以后只把服务端迁到服务器，客户端继续通过API使用。不用Docker。

## API契约草案（尚未实现）

- POST /auth/login：登录，返回短期访问凭据。注册/账号创建机制、密码哈希、过期/撤销策略在实现前单独定，不明文存密码。
- GET /sessions：列出当前认证用户的会话。
- POST /sessions：为当前用户新建会话，客户端不能代填任意owner。
- GET /sessions/{id}/messages：读取属于当前用户的完整历史。
- POST /sessions/{id}/turns：提交问题，服务端通过SSE返回增量和终态。
- POST /sessions/{id}/turns/{turn_id}/cancel：取消属于当前用户的运行任务。

接口路径不等于实现，必须有鉴权和归属检查。访问其他人的会话统一用不泄露存在性的错误。不采用GET查询参数传问题/令牌，避免URL日志泄漏。部署远程时使用HTTPS。

## SSE事件约定草案

turn_started带服务端turn_id；text_delta带正文片段；usage带可得用量；turn_completed仅在完整轮次成功保存后发送；turn_failed/cancelled明确失败，不把已经显示的部分文本当完整答复。缓存命中有独立标记，仍保持同一事件协议，不能伪造模型调用/TTFT。

网络chunk不是SSE事件边界，客户端使用成熟解析器处理换行和UTF8。浏览器关闭/CLI断线不天然等于业务撤销；第一版策略拟为连接断开主动取消并等待清理，同时提供显式cancel和状态核验。完成但最终确认包丢失时，客户端先查轮次状态，不能自动重复请求。

## 数据/并发设计还需补的内容

现有users只有本地标识，没有密码哈希或认证表；不能把--user选项搬到HTTP请求当登录。现有SessionStore是同步单连接实现，不能在异步FastAPI里随意共享同一连接跨线程；实现服务端时需按请求/任务管理连接，选择适当异步适配与事务策略，避免阻塞事件循环。

现有乐观轮次计数只拦截提交冲突，不能避免两个同会话任务已经花费模型token。服务端需定义同会话串行/忙时拒绝，跨会话限并发；使用服务端用户身份、会话ID隔离。任务状态和request_id/幂等请求键需设计，不能拿回答缓存代替任务幂等。

## 按步骤迁移

1. 先确定CS目标与接口（当前文档），保留本地可运行核心。
2. 抽应用服务：统一“读历史→选上下文/摘要→缓存→图执行→事务保存”；CLI不再承担这些业务。
3. 做服务端健康检查和开发账号认证，真实SQLite迁移与隔离测试；只绑定127.0.0.1，不先公网开放。
4. 接单次SSE流，CLI只与服务端通信；验证断线、取消、终态保存与无Key下发。
5. 接会话列表/切换、任务状态、限流与幂等，再实现长期偏好和真实MCP卡牌工具。

不在用户需求还在确认时一次生成登录、多用户生产服务和所有工具。第一版用户可见的成功标准：客户端无模型Key，服务端隔离用户/会话，能流式显示、恢复会话，日志可追踪且无凭据。
