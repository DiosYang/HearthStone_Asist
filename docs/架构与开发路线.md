# 架构与开发路线

实现更新：原规划中的网页版CS与认证、会话、SSE、明确偏好保存已落地；未接MCP/卡牌工具。下文含原阶段规划，当前实现、启动和验证以README及《网页版-启动与边界》为准。

## 技术约定

单个炉石助手，DeepSeek+LangChain模型接口、LangGraph编排、未来MCP业务工具。目标CLI客户端+FastAPI服务端，不用Docker、不执行任意代码。当前仍是本机开发入口，不是已完成的CS应用。

先传统对战；标准/狂野、版本不清楚先澄清，暂不做酒馆战棋、实时游戏进程读取或代打。卡牌、模式合法性、补丁、胜率等需可核验来源；模型记忆不能冒充最新数据。

## 现有模块边界

- agents：选择prompt与上下文，图状态和步骤，不拼API请求或直接写SQL。
- models：LangChain真实DeepSeek调用、流式片段、结束状态、用量；Key仅供模型接口，不进State或日志。
- prompt：系统职责/任务要求，不赋予工具权限。资料和偏好不直接提升为system。
- memory：记忆策略与上下文选择，存取委派storage。
- storage：SQLite事务与用户/会话归属检查，不决定模型怎么回答。
- cache：完整实际请求指纹，不能只按问题字符串复用。
- log：运行证据，记录关联ID/节点/请求阶段/耗时/可得usage，不记录Key、认证头或完整正文。

__main__.py目前承载开发CLI和少量应用流程；CS迁移时先抽应用服务再接路由，不把业务复制到两个入口。现有同步SQLite单连接不能直接跨并发HTTP请求共享。

## 三类记忆

短期记忆：按session_id隔离的对话缓冲，可落盘恢复；当前保存完整question/answer轮次，未来工具链加入时需迁移消息结构。完整历史与实际发送上下文分开，摘要有损、保留原文。

长期记忆（待实现）：按user_id归属的已确认偏好，如职业、套牌风格、预算、回答详细度。需确认、来源/时间、查看/修改/删除、相关性与注入预算；模型推测不直接保存。/new或新会话不删除长期偏好，本次明确需求优先旧偏好。不保存凭据。删除偏好不自动擦除旧历史/日志，需明确告知。

工作记忆：agents的本轮LangGraph State是权威，memory不另建一份会漂移的状态。目前只有question/messages/answer，未来加入套牌/模式/版本、待消歧候选、工具依据、步骤和预算。跨用户/任务隔离，切换任务清理旧派生数据；不是自动检查点，也不意味着重启可续跑。

三类记忆不要求三个数据库。卡牌库、规则资料和RAG索引是知识来源，不混为个人记忆。

## 流式、预算与日志

LangChain.astream交出片段，模型层只接受当前支持的文本，终端立即刷新；片段不等于一个token。首可见文本延迟与服务器首token生成时间不同。当前主输出上限1024；缺stop或截断报错，不保存半轮。Ctrl+C等待流/连接退出，不自动重试。没有工具时不虚构工具日志。

上下文按UTF8字节+余量做保守预算，不是精确tokenizer。超预算才请求摘要，每次最多3批，原文不删除。摘要也消耗token，缓存命中不撤销已产生的摘要费用；估算和摘要均不能绝对保证不触及供应商窗口。精确缓存15分钟且按用户/会话隔离，历史变化通常导致不命中。

## 接下来按这个顺序

1. 在现有本地CLI核对一轮真实流式与同会话继续；不替用户代跑收费请求。
2. 抽应用服务，做CS认证、会话接口和SSE，用户身份从服务端认证取得。
3. 明确同会话并发、取消、幂等、完整提交和日志语义。
4. 接受信的真实卡牌数据源和只读MCP服务，再扩为model→tools→model。
5. 补长期偏好与工具缓存，明确数据版本/来源时间与删除策略。
6. 按实际需求做规则资料检索、套牌码解析与确定性统计。
7. 用真实失败样本评测工具选择、参数错误、来源支持、成本和时延。

未来client负责交互与HTTP/SSE，server负责认证/任务生命周期，tools/mcp负责服务端工具协议适配。未实现前不创建空目录，不因为“正规”就过早拆微服务。

参考：[LangGraph应用组织](https://docs.langchain.com/oss/python/langgraph/application-structure)。它是参考而非统一标准；本项目本地ainvoke不要求langgraph.json，也不要求第三方追踪平台。
